仕入れマップ

本せどりの店舗回りを楽にする、無料のスマホ用アプリです。全国のブックオフ 780店の場所と営業時間が入っていて、今いる所から近い順に出ます。行った店を記録して、次にどこへ行くかを決めるための道具です。

  • 使う：https://naitou0121.github.io/sedori-map/
  • ログイン不要・広告なし・費用ゼロ。記録はスマホの中にだけ残り、どこにも送られません
  • 中身はすべて公開（MITライセンス）。自分用に書き換えて、自分の版を配ってOK

制作：納豆（@nattou091）。NASOラボの皆さんへの贈り物として作りました。

1. 使い方

入れ方（1分）

  1. iPhone：Safari で上のURLを開く → 画面下の「共有」ボタン → ホーム画面に追加
  2. Android：Chrome で開く → 右上「⋮」 → ホーム画面に追加（または「アプリをインストール」）
  3. 開いた時に位置情報を聞かれたら「許可」。近い順の計算と地図の現在地にだけ使い、保存も送信もしません

ブラウザのまま使っても動きますが、ホーム画面に入れると全画面になり、圏外でも開けます（地図の絵だけ通信が要ります）。

ブックチケットの対象店（2026-11-11 追加）

ブックオフの「ブックチケット」（月額の会員券）が使える店に チケット可 の札が付きます。全国7地域・172店ぶんです。

  • 「店舗」「地図」の上の チケット可 を押すと、対象店だけになります
  • 「店舗」「地図」の上の緑のボタン チケットを開く で、会員券のページ（sub-ticket.jp のマイページ）がそのまま開きます。対象店の一覧（公式） で、その地域の今の対象店を確かめられます
  • 店の詳細にも、チケットが使える店かどうかが出ます。「店舗」の検索で店名を入れれば、その店が対象かすぐ分かります
  • 対象店は公式ページ（sub-ticket.jp）の 2026-11-11 時点の表示を写したものです。対象から外れた店や追加された店は、自動では反映されません。直す時は data/ticket.json を書き換えて build.py を実行します

メモ

店の詳細に メモ の欄があります。駐車場のこと、駅からの道、棚の傾向など、自由に書けます。書くと自動で残り、一覧にも最初の1行が出ます。メモはこのスマホの中だけに残ります。

駅からの徒歩

電車で回る人向けに、最寄り駅からの徒歩が出ます（例：JR岐阜駅 徒歩15分）。店の詳細には、公式ページの「アクセス」の文（電車・バス）がそのまま出ます。公式ページに徒歩の分数が書かれていない店には出ません。

駐車場

各店に、駐車場があるかどうかと台数が出ます（例：P 60台／駐車場なし）。ブックオフ公式の店舗ページに載っている表記です。

  • 公式ページには「有料か無料か」は載っていません。分かった店は、店の詳細の駐車場の欄で 無料／有料 を自分用に付けられます。付けると一覧にも「P 60台・有料」のように出ます
  • 自分で付けた印は、このスマホの中にだけ残ります

現在地が取れない時

「店舗」の上に、使っているブラウザに合わせた直し方が出ます。位置情報を使いたくない時は、同じ場所の欄に地名や駅名（例：岐阜駅）を入れて「ここから測る」を押すと、そこから近い順に並びます。

よく使う流れ

  1. 「店舗」を開く → 近い店が上から並ぶ
  2. 「近い順に5店で今日の予定を組む」 → 回る順に並ぶ → 「Googleマップで案内」 でまとめて道案内
  3. 店に着いたら「行った」（または予定のチェック）。前回からの日数が店ごとに残る
  4. 店の詳細（店名を押す）で、しばらく行かない店は「1ヶ月寝かせる」、もう行かない店は「非表示」

絞り込みのチップ

  • お気に入り：店の左の星を押すと入る。押すとお気に入りの店だけになる
  • チケット可：ブックチケットの対象店だけになる
  • チケットを開く（緑）：会員券のページを開く
  • 近く／県名：「近く」は県で絞らず近い順。県名を押すとその県の店（県は近い順に並ぶ）
  • チェーン名のチップ：店データが2チェーン以上入っている時だけ出る。押すと表示から外せる
  • 一覧に出るのは本を置いている店だけです（ブックオフには本を置かない業態 Rehello・aidect・あそビバ などがあります）。最初は近い順に40店、「もっと見る」で続きが出ます

店を自分で足す（他のチェーン・個人店）

設定 →「店を足す」。店名・住所・営業時間・種類（任意）を入れて「追加」。住所から位置を取って地図にも出ます。

まとめて足す：表計算（Excel・スプレッドシート）で 店名, 住所, 営業時間, 種類 の4列を作り、コピーして「まとめて足す」の欄に貼る → 「まとめて追加」。1店ずつ位置を取るので、30店なら30秒ほど。位置が取れなかった行は欄に残るので、住所を直して再実行。

足した店は「自分で追加」のタグが付き、あなたのスマホの中だけに保存されます。

控え（バックアップ）と機種変更

訪問記録・足した店・設定はこの端末の中だけにあります。機種変更やブラウザのデータ消去で消えるので、設定 →「控えを作る」→「コピー」でメモアプリなどに控えてください。新しい端末では「控えから戻す」に貼れば戻ります。

注意

  • 営業時間は各チェーンの公式サイトなどから取ったもので、祝日・臨時休業は入っていません。行く前に店舗詳細の「公式ページ」で確認を
  • 店データはアプリの更新で差し替わります（起動直後に「新しい版があります」と出たら「更新する」）
  • 位置情報は端末の中で距離計算にだけ使います。住所から位置を取る時だけ、国土地理院の住所検索（公的・無料）に住所文字列を送ります

2. 仕組み

サーバーもデータベースもありません。GitHub Pages に置いた静的ファイルだけで動く PWA（ホーム画面に入れられるWebアプリ）です。

sedori-map/
├ src/body.html         ← アプリ本体（画面・動き）。直すのはここだけ
├ build.py              ← ビルド：下の4つを作り直す
├ index.html            ← build.py が作る。配布される本体（直接編集しない）
├ guide.html            ← build.py が README.md から作る手引き（このページ）
├ sw.js                 ← オフライン用のサービスワーカー（版の番号は build.py が進める）
├ data/
│  ├ sources/           ← チェーンごとの店データ（1チェーン1ファイル）
│  │  └ bookoff.json    ←   ブックオフ 780店（fetch_bookoff.py が作る）
│  └ stores.json        ← build.py が sources/* を合流させたもの（直接編集しない）
├ fetch_bookoff.py      ← ブックオフ公式の店舗検索から店データを取り直す
├ tools/
│  ├ csv2json.py        ← CSV → data/sources/<チェーン>.json（他チェーンを足す道具）
│  └ 見本.csv           ←   CSVの書き方の見本
├ deploy.sh / 公開.command ← ビルド → GitHub に push → 1〜2分で本番に反映
├ manifest.webmanifest / icon-*.png ← ホーム画面アイコンなど
└ leaflet.js / leaflet.css ← 地図ライブラリ（Leaflet・BSD-2）

データの流れ

  1. data/sources/*.json にチェーンごとの店が入っている。各ファイルは chain（チェーンの名前・色・本を扱うか・出どころ）と stores（店の配列）を持つ
  2. python3 build.py が全部を data/stores.json にまとめ、src/body.html から index.html を作り、README.md から guide.html を作り、sw.js の版を進める
  3. アプリは起動時に data/stores.json を読み、端末内にキャッシュ。訪問記録などは localStorage に保存
  4. 地図の絵は国土地理院タイル、住所→位置は国土地理院の住所検索API。どちらも無料・キー不要

店1件の形

{"id":"bo20374","chain":"bookoff","name":"BOOKOFF 札幌南2条店","brand":"BOOKOFF",
 "address":"北海道札幌市中央区南二条西1-3","pref":"北海道","city":"札幌市中央区",
 "lat":43.0584,"lng":141.3561,"hours":"10:00～21:00","hours2":"","tel":"011-200-5777",
 "url":"https://www.bookoff.co.jp/shop/shop20374.html"}
  • id は全チェーンで重複しないように（ぶつかると build.py がチェーンIDを頭に付けて逃がす）
  • hours は 10:00～21:00 の形なら営業中判定に使う。翌1:00 や 〜 - も読める。読めない形は「営業時間 不明」として表示だけ
  • brand は業態・店の種類。チェーン名と同じなら省略可。【閉店】 を含む店はアプリ側で除外

自分で足した店・記録の置き場所

localStorage の sedori-map-v1 に1つのJSONで入っています（visits 訪問記録・custom 足した店・hidden 非表示・snooze 寝かせ・home 出発地・prefs 絞り込み・plan 今日の予定）。「控えを作る」で出る文字列はこれそのものです。

3. 改造する

必要なもの：Mac か Windows か Linux のパソコン、Python 3（Macは最初から入っています）、GitHub のアカウント（無料）。プログラミングの経験は要りません。手順どおりに打てば動きます。

3-1. 自分の版を持つ（フォーク）

  1. https://github.com/naitou0121/sedori-map を開き、右上の Fork → 自分のアカウントに複製
  2. 複製したリポジトリの Settings → Pages → Branch を main / (root) にして Save
  3. 1〜2分で https://<あなたのID>.github.io/sedori-map/ で自分の版が開く
  4. パソコンに取ってくる：ターミナルで git clone https://github.com/<あなたのID>/sedori-map.git → cd sedori-map

以後、直したら ./deploy.sh "何を直したか"（Windows は python3 build.py → git add -A → git commit -m "..." → git push）で自分の本番が更新されます。

3-2. 他のチェーンの店を足す（いちばん多い改造）

例：「古本市場」を足す。

  1. 表計算で店の一覧を作り、CSV で保存する。列は name,address,hours,hours2,tel,url,brand（name と address だけ必須）。見本は tools/見本.csv
  2. ターミナルで
python3 tools/csv2json.py 古本市場.csv --id furuhon --name 古本市場 --short 古本 --color "#2a7a3b" --books
python3 build.py
  1. ブラウザで index.html を開いて確かめる（ローカル確認は python3 -m http.server 8000 → http://localhost:8000/ ）
  2. ./deploy.sh "古本市場を追加" で公開

--id はチェーンの英字ID（ファイル名と店IDの頭に使う）、--name は表示名、--short はチップ用の短い名前、--color はピンの色、--books は本を扱う店なら付ける（「本がある店」の絞り込みに入る）。

住所から位置を取るのに1店1秒かかります。位置が取れなかった行は最後にまとめて出るので、住所を直して再実行（取れた行は使い回す）。座標が分かっている店は lat,lng 列を足せば住所検索を飛ばします。

公式サイトに店舗一覧がある場合は、fetch_bookoff.py を真似て取得スクリプトを書くこともできます。ポイントは 出力を data/sources/<id>.json にすること。その先は build.py が面倒を見ます。

他社サイトからデータを取る時は、そのサイトの利用規約と robots.txt を確認し、間隔を空けて（1秒以上）取ってください。ブックオフのスクリプトは1都道府県1リクエスト・1.2秒間隔です。

3-3. ブックオフのデータを取り直す（営業時間が変わった・新店）

python3 fetch_bookoff.py
python3 build.py
./deploy.sh "店舗データ更新"

公式の店舗検索が裏で使っている公開APIから取ります（約1分）。

3-4. 見た目・文言・動きを変える

src/body.html が唯一の正本です。上から CSS → 画面のHTML → JavaScript の順。

  • 色：先頭の :root{--accent:...} など。ダークモードは @media (prefers-color-scheme:dark) の中
  • 「2週間以内＝緑／30日以上＝赤」の閾値：JavaScript の gap() 関数（d>=30 と d>=14）
  • 今日の予定の店数（5店）：quickPlan() の slice(0,5)
  • 一覧に最初に出す件数（40件）：nearLimit
  • 文言はすべて HTML か JavaScript の中に日本語で直書きなので、検索して置き換えればOK

直したら python3 build.py（または ./deploy.sh）。index.html を直接直しても次のビルドで消えます。

3-6. 困った時

  • 直したのにスマホで変わらない：起動直後に「新しい版があります」が出るまで数回開き直す。出ない時は 設定 → 診断 →「今すぐ確認」。それでもダメなら build.py を通したか（index.html の app-version が進んだか）を確認
  • build.py がエラー：data/sources/*.json のどれかが壊れている可能性。エラーメッセージのファイル名を見る
  • 位置が取れない住所：番地の前までで止めると取れることが多い（「○○市△△町1-2-3 ビル名」→「○○市△△町1-2-3」）
  • GitHub Pages が 404：Settings → Pages で Branch が main / (root) になっているか。有効化直後は数分待つ
